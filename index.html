什么是 Harness Engineering？

Harness Engineering 是围绕大语言模型（LLM）构建 生产级代理系统 的工程实践。它不涉及模型训练或微调，而是专注于让 LLM 安全、高效、可控地完成复杂任务。

核心挑战

  • 如何让 LLM 安全地调用外部工具
  • 如何管理多步骤任务的执行流程
  • 如何处理上下文窗口的限制
  • 如何协调多个代理协作
  • 如何持久化状态和恢复会话
  • 如何按需注入领域知识

Claude Code 的方案

Claude Code 用 12 层渐进式 Harness 机制 解决这些问题。每一层都在前一层的基础上叠加新能力，从最简单的主循环到完全自主的代理团队。

12 层渐进式 Harness 机制

每一层都在前一层基础上叠加，从最基础的 API 调用循环到完全自主的代理团队协作。

01

主循环 — The Loop

「一个循环 + Bash 就够了」

A while(true) loop in query.ts calls Claude API, checks stop_reason, executes tools, appends results.

// src/query.ts — 主循环核心 (1729 行中的一小部分)
export async function* query(params) {
  const terminal = yield* queryLoop(params, consumedCommandUuids)
  // ... 异步生成器，全链路流式
}

async function* queryLoop(...) {
  while (true) {
    yield { type: 'stream_request_start' }
    
    // 调用 Claude API（带 fallback 支持）
    for await (const message of deps.callModel(...)) {
      // 处理 assistant 响应
      yield message
    }
    
    // 检查 stop_reason
    // 'tool_use' → 执行工具
    // 'end_turn' → 结束
    // 'max_tokens' → 截断处理
    
    // 执行工具并追加结果
    const toolResults = await runTools(toolUseBlocks, ...)
    for (const result of toolResults) {
      yield result  // tool_result 追加到 messages[]
    }
  }
}

核心区别：tool_result vs 系统提示

维度 塞入系统提示 通过 tool_result 注入
Token 消耗 ⚠️ 每次请求都消耗 ✅ 仅调用时消耗
上下文占用 ⚠️ 始终占用（可能 10K+ tokens） ✅ 仅元数据（~1%）
知识更新 ⚠️ 需重新加载所有 prompt ✅ 按需重新加载
可扩展性 ⚠️ 受上下文窗口限制 ✅ 无数 Skills（按需加载）
权限控制 ⚠️ 无细粒度控制 ✅ per-skill 权限 + safe props 白名单

Skill 执行流程

1
发现

系统启动时加载所有 Skills，去重后注册到 Command Registry。名称 + 描述写入系统提示（≤1% 上下文窗口）。

2
匹配

用户输入后，Claude 在可用 Skills 列表中查找匹配项。匹配依据：whenToUse 描述、用户显式输入 /skillname。

3
权限检查

三层检查：deny rules → allow rules → safe properties 白名单。默认 ask 用户。

4
内容加载

加载 SKILL.md 完整内容。处理 frontmatter、执行 !command 替换、替换 $ARGUMENTS 占位符。

5
注入 & 执行

Inline 模式：内容作为 createUserMessage({ content, isMeta: true }) 直接注入 messages[]。
Fork 模式：在独立 sub-agent 中执行，拥有自己的 token 预算和工具权限。

SKILL.md Frontmatter 完整参考

---
# 必填

Budget 控制机制

Skills 列表占用 ≤1% 上下文窗口（默认 ~8,000 字符）。超过时的处理策略：

① Bundled Skills 优先保留完整描述
② 剩余 budget 分配给非 bundled Skills
③ 每个描述最多 250 字符
④ 极端情况：非 bundled 降级为仅名称

Skills 权限系统

Skills 有独立的三层权限检查，不同于工具的权限系统：

1. Deny Rules

用户配置的拒绝规则。支持精确匹配和前缀匹配（review:*）。

2. Allow Rules

用户配置的允许规则。匹配则直接放行。

3. Safe Properties Whitelist

如果 Skill 仅包含安全属性（name, description, model 等），自动放行。新增属性默认要求权限。

4. Ask User

以上都不匹配 → 弹出权限请求，用户可选择临时/永久放行。
